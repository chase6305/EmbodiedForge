# RL 训练运行与恢复校验记录（2026-09-28）

本轮修复 RLinf 长任务的代码来源隔离、SAC 实际恢复状态校验，以及启动器正常退出后遗留子进程的问题。使用同一保存点做旧版/新版续训对照，两次保存的完整权重和最终 FP32 ONNX 文件逐字节一致。机械鸭的有限值检查合并没有稳定加速，已撤回，只保留评估循环耗时记录。

全部训练和仿真使用 headless，主入口为 `ef`，依赖放在独立 SDK。没有增加启动冒烟、改变奖励、替换默认模型或修改外部仓库。原始产物位于 `runs/rl-runtime-robustness-20260928/`；可随代码审阅的汇总见[结构化数据](rl-runtime-validation-20260928.json)。

## 三项修复及验证

**代码快照。** 旧 RLinf 启动器通过软链接加载工作区；长任务期间继续修改源码，后续导入可能读到新版本。现在复用现有快照机制，把本地适配代码及相关资源复制到运行目录的 `implementation/embodiedforge`，记录 SHA256，并在 SDK 入口核对加载位置与文件内容。SDK 子进程继承该路径。外部 RLinf 仍固定在 `67864d67c086a111de9921c5f4591eb5882f74ec`，没有移植其训练器。

**实际 DCP 恢复状态。** 原先检查保存点布局、DCP 分片范围和独立权重，不能发现实际恢复状态中的损坏。本轮复制一个有效保存点，将 DCP 中的熵温度 `base_alpha` 改为 NaN：旧检查接受，新检查在启动 Ray/GPU 前拒绝，原始保存点未改动。

新检查读取 CPU DCP 状态，核对策略张量与 `full_weights.pt`、熵温度布局与有限值，以及 actor、critic、熵温度的 Adam 参数顺序、超参数、步数、动量缓冲。复用已有 Adam 校验器；真实 DCP 回归覆盖健康状态、NaN 温度、负二阶矩、缺失缓冲和策略不一致。10 个历史保存点全部通过兼容性审计。该范围不包括回放轨迹张量和调度器的完整语义校验，也不补全仿真与随机流恢复。

**正常退出后的清理。** 实际进程复现表明：主进程返回 0，且子进程把输出重定向后，旧启动器会遗留子进程。现在成功、失败和中断都清理本次进程组。已有进程生命周期测试补充两种正常退出情况；修复前两例失败，修复后通过。清理范围仍为本次拥有的进程组。

## 机械鸭：撤回没有稳定收益的改动

尝试把每步观测和动作的有限值检查合并为一次 GPU 到 CPU 同步。使用固定第 5999 次更新检查点，32/128 个环境，前进 `[0.2, 0, 0]` 和转向 `[0, 0, 0.6]`，seed 121/122，共 8 组配对、16 次评估。每次 3000 步，即每环境 60 秒仿真；关闭推力，其他条件保持 `play=True`。基线仅增加同样的计时，按组交替两版运行顺序，GPU 任务串行。

| 环境数 | 指令 | seed | 原检查 / 秒 | 合并检查 / 秒 | 耗时变化 |
| ---: | --- | ---: | ---: | ---: | ---: |
| 32 | 前进 | 121 | 40.519 | 40.625 | +0.26% |
| 32 | 前进 | 122 | 42.630 | 41.053 | −3.70% |
| 32 | 转向 | 121 | 41.575 | 40.918 | −1.58% |
| 32 | 转向 | 122 | 40.561 | 40.911 | +0.87% |
| 128 | 前进 | 121 | 43.197 | 43.520 | +0.75% |
| 128 | 前进 | 122 | 43.106 | 44.482 | +3.19% |
| 128 | 转向 | 121 | 43.529 | 43.894 | +0.84% |
| 128 | 转向 | 122 | 43.258 | 43.092 | −0.38% |

只有 3/8 组更快，耗时变化的均值为 +0.03%、中位数 +0.50%。本轮没有观察到稳定收益，最终恢复原检查顺序。保留的 `evaluation_seconds` 从首次观测就绪、GPU 同步后计时，覆盖策略、物理及逐步检查，不含环境创建、加载和清理。最终 worker 与上述计时基线完全一致。

各配对的终止计数相同，但奖励与跟踪数值存在小幅差异，没有逐位轨迹等价性结论。128 环境 seed 121 的前进、转向各发生一次跌倒，因此这些评估不代表机械鸭已达到真机部署要求。本轮也补充 `python -m embodiedforge microduck ...` 统一入口；原有模块入口继续可用。

## 从头训练与后训练

按预先记录的协议，从 seed 2026 随机初始化完成 5000 轮训练，32 个环境，每 1000 轮评估并保存。训练于 UTC 15:06:01–16:02:53 执行；随后导出 FP32 ONNX，并用 seed 9301、9302、9303 各完成 160 条独立闭环轨迹。

时间允许后，从这份完整第 5000 轮保存点追加 1000 轮，显式使用 `--save-interval 500 --eval-interval 250`，再导出并评估相同三个种子。续训于 UTC 16:03:43–16:15:12 执行，最后一次独立评估于 16:16:01 完成，位于原定 14:18:42–16:18:42 的两小时窗口内。最终审阅与文档补齐于次日完成。

本次继续训练后，曾成功、结束成功比例分别降低 1.250、1.875 个百分点。保留两份模型，不把更晚保存的模型自动当作更优模型。这是一条训练轨迹的完整状态续训，评估频率也发生变化；不能解释为单独增加训练预算或单独改变评估频率的因果效应，也不是不中断的 6000 轮训练。5000 轮的 480/480 同样不代表其他种子、任务或真实机器人必然成功。

前一阶段的 5 个保存点及后一阶段的 2 个保存点全部通过实际 DCP 检查。第 5000/6000 轮的三个 Adam 优化器分别累计 160,000/192,000 次更新，回放累计 320,000/384,000 条转换。完整保存点分别为 167,729,553/199,445,551 字节，FP32 ONNX 均为 575,951 字节。快照哈希在运行后仍通过核对。

实际 TensorBoard 事件确认，新参数使续训在累计第 5250、5500、5750、6000 轮评估，而保存点为 5500、6000；日志 step 从零计数，分别写为 5249、5499、5749、5999。参数须为正数并整除保存间隔，省略时仍保持旧命令行为。

辅助核对发现，本次与历史 seed 2026 的第 1000 轮权重不同。实际配置中，本次保存/评估间隔为 1000，历史运行为 500，计划总预算也不同，因此不能将差异归因于适配代码。前述同一起点、同一配置的旧版/新版续训才是本轮正式的软件对照。

复现两阶段训练时使用新的输出目录：

```bash
conda activate ef
study_output=runs/rl-runtime-reproduction
sdk_python="$PWD/.cache/rlinf-sac-venv/bin/python"

python -m embodiedforge rlinf train \
  --repo /home/ubuntu/workspace/3rdparty/RLinf --python "$sdk_python" \
  --output "$study_output/fresh" --gpu 0 --headless --quiet \
  --iterations 5000 --save-interval 1000 --seed 2026 --num-envs 32

python -m embodiedforge rlinf train \
  --repo /home/ubuntu/workspace/3rdparty/RLinf --python "$sdk_python" \
  --resume "$study_output/fresh/maniskill_sac_mlp/checkpoints/global_step_5000" \
  --output "$study_output/post" --gpu 0 --headless --quiet \
  --iterations 1000 --save-interval 500 --eval-interval 250
```

SDK 路径是本机已经验证的独立环境；其他机器按 [RLinf 指南](rlinf.md) 安装后替换。实际导出、评估命令保存在各阶段的 `fresh-training.json`、`post-training.json` 中，评估使用最终 FP32 ONNX、16 环境、10 个 rollout epoch。
