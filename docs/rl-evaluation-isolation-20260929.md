# RLinf 评估随机状态隔离验证（2026-09-29）

本轮追查[上一轮](rl-runtime-validation-20260928.md)观察到的现象：相同训练种子、不同训练内评估频率可能产生不同权重。实际复现确认，固定版本的 ManiSkill 自动重置会消耗环境进程内的 CUDA 随机流，影响后续训练重置。适配层现在在整次环境评估调用外保存并恢复 Torch 随机状态。

修复不移植外部训练器，不修改损失、奖励、模型或评估内部的计算。默认仍为 headless，`ef` 负责启动，独立 RLinf SDK 执行计算。原始产物位于 `runs/rl-evaluation-isolation-20260929/`。

## 如何定位副作用

先使用实际 MLP 与已训练权重检查策略推理。在 eager 与 `torch.compile` 两种模式下，第一次和再次执行确定性评估均不改变 CPU/CUDA RNG；插入评估后，下一个随机训练动作与未插入时精确一致。因此没有修改模型推理。

随后在同一进程创建 32 个训练环境和 16 个评估环境。训练环境先推进 10 步，评估环境执行完整 50 步并触发自动重置。对比评估前后的训练观测及随机状态：

| 观测项 | 原行为 | 在整次评估外隔离 Torch RNG |
| --- | --- | --- |
| 训练环境当前观测 | 不变 | 不变 |
| CPU Torch RNG | 不变 | 不变 |
| CUDA Torch RNG | **改变** | 不变 |
| NumPy / Python RNG | 不变 | 不变 |

固定 ManiSkill 版本在有显式 seed 或开启 enhanced determinism 时，会在 episode 初始化外使用 `torch.random.fork_rng`。当前配方的自动重置未显式传入 seed，因此可消耗进程共享的 CUDA RNG。训练和评估环境位于同一个 EnvWorker，评估后的随机状态因而会影响之后的训练重置。这里观察到的是随机状态副作用，没有观察到评估推进训练环境当前物理状态。

修复在当前入口使用上游 EnvWorker 的局部子类，覆盖 `evaluate`，以 `torch.random.fork_rng` 包住原方法；上下文覆盖 CPU 和评估环境使用的 CUDA 设备，异常退出也恢复状态。作用域结束后仍执行上游原有清理。入口调用结束会恢复原 EnvWorker 引用，没有向外部仓库写入修改。

请求记录 `evaluation_rng=isolated-torch`。缺少该字段的历史请求继续采用 `upstream`；通过新 CLI 创建的续训采用新语义。隔离不会重新设定评估种子，保证范围是当前固定同步配方的 Torch 随机状态，不扩展为所有随机库、多机或异步训练的承诺。

真实训练首次到达评估点时，最初实现因环境使用 `torch.device("cuda")`、设备编号为 `None` 而失败。已改为先解析当前 CUDA 设备，并增加实际 CUDA 正常/异常退出覆盖。失败产物和最初候选源码以 `v1-failed-` 前缀保留；正式候选重新冻结源码，从同一原始保存点重跑完整预算，未将失败路径纳入配对结果。

## 配对训练协议

基线使用本轮修改前的本地代码快照，包含上一轮尚未提交的修复；不能简单用 Git HEAD 代替。修复版单独冻结源码，两个快照均记录文件哈希。外部 RLinf 固定在 `67864d67c086a111de9921c5f4591eb5882f74ec`，保持干净状态。

从已存在的第 2000 轮完整保存点追加 **1000 轮**，32 个环境，每 500 轮保存；比较评估间隔 250 与 500。所有 GPU 任务串行执行，保存点来源和执行顺序在 `protocol.json` 中预先记录。

原计划对两个训练种子都运行完整四组合。第一条训练尚未完成时，实测更新耗时约 0.90 秒/轮；为符合两小时预算，在不查看学习结果的情况下收敛队列，保留以下六条完整训练。`protocol-initial.json` 保留初始方案，修订时间和理由保留在最终协议。每条训练仍追加 1000 轮，没有中途缩短预算。

| 训练种子 | 原行为 / 评估 500 | 原行为 / 评估 250 | 隔离 / 评估 500 | 隔离 / 评估 250 |
| --- | --- | --- | --- | --- |
| 1234 | 完成 | 完成 | 完成 | 完成 |
| 4321 | 按时间条件跳过 | 按时间条件跳过 | 完成 | 完成 |

六条主队列中，seed 1234 提供完整的软件与频率对照，seed 4321 复核修复后的频率一致性。随后在两条基线比较尚未完成时预先登记了可选控制组：若主队列连同评估于 UTC 04:45 前完成，则为 seed 4321 补齐两条原行为训练及独立评估，否则整体跳过可选组。该条件只依赖时间，不依赖学习结果，见 `optional-protocol.json`。每个种子的分支共享相同输入保存点，因此不是六次独立的从头训练。独立 ONNX 评估实际使用 seed 9401、9402、9403，各 16 环境 × 10 个 rollout epoch，共 480 条轨迹/模型。

不同训练内评估频率会改变评估环境自身已经执行的轮数，因此不直接用两条训练日志中最后一次评估分数判断策略是否相同。保存点内容比较检验训练状态；在相同独立环境种子下的闭环评估检验最终策略行为。

本轮网络没有扩容：完整模型含 435,466 个参数，其中训练 actor 为 144,648、双 critic 共 290,818；`full_weights.pt` 为 1,754,385 字节。部署只保留确定性 actor，移除探索用 log-std head 和 critic，参数数为 143,620。完整续训保存点还包含 Adam、熵温度、目标网络和回放数据，其磁盘大小不能当作模型权重大小；各运行的实际字节数在结构化结果中分别记录。

| 文件或目录 | 参数量 | 实测文件字节数 |
| --- | ---: | ---: |
| 完整模型 `full_weights.pt` | 435,466 | 1,754,385 |
| FP32 部署模型 `policy.onnx` | 143,620 | 575,951 |
| 完整第 3000 轮续训保存点 | 包含模型及训练状态 | 104,297,695 |

目录大小按文件字节数求和，不包含文件系统分配开销，也不包含运行日志和复制的输入保存点。

完整恢复状态另在 CPU 上通过 DCP 元数据读取，并递归比较实际张量和标量，避免把序列化元数据的变化当作训练变化。策略侧比较 201 项、熵温度侧 30 项，包含模型、优化器及保存的随机状态；2500/3000 轮对应 Adam 更新步数为 80000/96000。

## 独立 PyTorch 评估入口

最后对同一份修复版权重、同一环境种子 9401，分别使用原行为入口和新入口执行 16 环境 × 10 轮独立 PyTorch 评估。两条路径均正常完成，全部任务指标完全相同：曾成功 156/160，结束成功 155/160。

相同模型在 CPU ONNX 闭环评估中为曾成功 158/160、结束成功 157/160。跨后端的闭环结果没有达到完全一致；本次原行为／新行为对照表明，这个差异不是评估随机状态隔离引入的。导出时的小幅动作数值误差不构成跨后端长期仿真一致性保证，本轮也未单独证明差异的全部成因。

进一步取最终保存点中最后 16 条回放片段的 1024 条实际观测，固定 batch=16，对同一观测比较 CPU ONNX 与三种 Torch 推理。最大动作绝对误差分别为 CPU Torch `1.304e-6`、GPU eager `1.371e-6`、GPU 编译 `1.281e-6`；没有发现非有限输出。这是训练回放上的数值核对，不是额外独立评估，也未证明这些微小误差就是全部闭环差异的成因。

这两条独立 PyTorch 路径另增加 320 条轨迹；连同 3360 条 ONNX 轨迹，本轮实际完成 3680 条闭环评估轨迹。它们不增加独立训练种子数量。

```bash

cd /home/ubuntu/workspace/chase/EmbodiedForge

  --repo /home/ubuntu/workspace/3rdparty/RLinf \
  --python .cache/rlinf-sac-venv/bin/python \

  --output runs/rlinf-eval-isolation-reproduce-250 \
  --iterations 1000 --save-interval 500 --eval-interval 250 \
  --gpu 0 --headless --quiet
```
