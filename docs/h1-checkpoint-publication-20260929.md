# H1 保存点发布与故障续训实测

本轮修复原生 H1 训练在保存权重时的一个恢复问题：旧实现先覆盖 `checkpoint.pt`，再更新 `run.json`。如果两次操作之间发生异常，运行记录仍引用旧哈希，权重文件却已经变成新内容，导致最后一个已记录的保存点也无法加载。新实现按更新轮数写入独立文件，提交运行记录后才清理旧权重。

保存与恢复对照共完成 3 个种子的完整训练对照、24 次固定指令评估和 6 条完整续训路径；全部可比较的训练指标与最终模型/优化器状态精确一致。本篇的主题是训练保存与恢复可靠性，没有调整 PPO 公式、网络、奖励或默认超参数。

## 实验范围与可复核材料

原始目录为 `runs/h1-checkpoint-publication-20260929/`，其中的训练产物和源码快照仅保留在本机，不随 Git 分发。[机器可读记录](h1-checkpoint-publication-20260929.json) 汇总协议、运行结果、源码与产物哈希，供 PR 审阅。

基线取自本轮开始时的工作区，不是直接运行 Git HEAD：工作区已有前几轮尚未提交的修复。基线和保存修复候选分别冻结到独立源码目录，逐文件哈希比较只有 `native_h1.py` 不同；训练不会随着后续编辑而改变实现。随后发现续训记录缺少输入权重身份，于是给最终版本增加 `resume_checkpoint_sha256` 字段并修正 CLI 帮助文字，另冻结到 `final-source`，通过独立的完整续训验证。原有对照继续使用其原始快照。

- 编排使用 `ef` 环境；H1 训练使用独立的 `.cache/external/mjbatch/.venv/bin/python`。
- 两侧均为 MuJoCo 3.11.0 / mjbatch 0.1.0 / Torch 2.9.0+cu128 / NumPy 2.5.2，物理仿真和 PPO 都在 CPU 上执行。
- 每项训练使用两个线程，无窗口、无渲染器；本轮实验按队列串行执行，不使用共享 GPU。
- 共享主机上的墙钟耗时只用于记录本轮成本，不作为吞吐性能结论。

## 故障发生在哪里

真实训练在第 50 轮正常提交一次权重。第 100 轮把新的权重临时文件重命名为正式文件后，故障脚本立即触发 `OSError`，模拟发布过程中的可处理失败。错误在真实 PPO 更新和实际文件重命名之后注入，没有替换学习器或构造假训练状态。

| 实现 | 运行记录的轮数 | 第 100 轮新权重 | 最后已记录保存点 |
| --- | ---: | --- | --- |
| 修复前 | 50 | 覆盖 `checkpoint.pt` | 无法加载，SHA256 不匹配 |
| 修复后 | 50 | 独立的 `checkpoint-000000100.pt`，尚未被记录引用 | 成功加载 `checkpoint-000000050.pt` |

两侧前 100 轮的损失、平均奖励、跌倒和超时计数逐项完全一致。故障运行原本请求 1000 轮，但在第 100 轮按协议中断，不能计作完成了 1000 轮训练。

另一个独立故障路径在相同发布边界向训练进程本身发送了真实 SIGTERM，验证生产信号处理器、最终记录和续训接口的组合行为。该实验不会给其他进程发送信号。

新发布流程为：

1. 校验 Adam 状态，将当前权重写入带轮数的临时文件并计算哈希。
2. 原子重命名新权重；旧记录引用的权重保持存在。
3. 原子提交 `run.json` 中的轮数、权重文件名与哈希，然后更新内存中的已提交状态。
4. 清理旧版本，通常保留当前和上一个已提交保存点。清理失败记录错误，不撤销已提交权重。

未提交的新权重可能留在失败目录，但加载不会按最大文件名猜测保存点。`--run` / `--resume` 始终读取 `run.json` 指定的文件。旧目录没有 `checkpoint` 字段时继续读取 `checkpoint.pt`；新目录不生成该别名，也无需增加新的启动参数。这是新程序读取旧目录的兼容，旧程序不能直接读取新的带轮数目录布局。

本改动保障已处理异常或中断时的文件一致性，不承诺断电持久性。SIGKILL 后仍标记为 `running` 的目录不会自动变成可恢复输入；首次保存前失败也没有可恢复权重。

## 完整训练对照

在读取完整训练结果之前声明三个训练种子：1234、4321、2026。每个种子分别运行旧实现和新实现，各从零训练 **10000 次 PPO 更新**，32 个环境、每轮 24 步、学习率 `0.0003`。每条路径的预算为 **7,680,000 条环境转换**。

这个预算与 [2026-09-25 学习率实验](rl-training-study-20260925.md) 不同：当时每条路径为 128 环境 × 24 步 × 5000 轮，共 15,360,000 条转换。本轮虽然更新轮数翻倍，环境转换数却只有当时的一半，训练种子和评估时长也不同；不能跨文章直接比较奖励或 RMSE 来判断策略进步。

执行顺序为旧/新 seed 1234、新/旧 seed 4321、旧/新 seed 2026。成对入队截止时间预设为 2026-09-29 13:36 UTC；一旦接受一对，就运行两条完整预算，不因结果好坏提前停止，也不缩短单条训练。若资源延迟导致某对尚未入队便超过截止时间，会同时排除该对并在记录中说明。

比较包括每轮损失、奖励、跌倒、超时，以及最终 policy、Adam 动量、步数和参数组。计时字段不纳入逐项相等判断。模型 MJB 文件独立核对哈希。

权重文件的 SHA256 用于验证各自文件的完整性，不能直接拿来判定不同保存格式的参数是否相同。PyTorch ZIP 序列化中的路径名称会受权重文件名影响；两侧文件字节不同，并不意味着张量不同。本实验实际反序列化后逐张量核对 dtype、shape 和精确值，同时递归核对其余状态。seed 1234 的两个 ZIP 容器在移除文件名前缀后，74 个记录的内容哈希也全部相同。

| 训练种子 | 每侧更新数 | 每侧环境转换数 | 全部非计时指标 | 最终 policy / Adam |
| --- | ---: | ---: | --- | --- |
| 1234 | 10,000 | 7,680,000 | 10,000 行精确相同 | 精确相同 |
| 4321 | 10,000 | 7,680,000 | 10,000 行精确相同 | 精确相同 |
| 2026 | 10,000 | 7,680,000 | 10,000 行精确相同 | 精确相同 |

合计完成 46,080,000 条从零训练环境转换。六个最终保存点的 17 个 Adam 步数均为 200000，符合每轮 5 个 epoch × 4 个 minibatch 的实际调用数。三条新格式从零训练最终均保留第 9950 和 10000 轮权重；两侧模型 MJB 的字节哈希相同。

三个种子均在截止前成对入队，没有排除或缩短任何训练路径。

## 续训与旧目录兼容性

预先规定每条续训路径新增 **1000 次更新**，32 环境 × 24 步，即各 **768,000 条新增转换**，统一使用 seed 8801，省略学习率参数以继承保存值。

- 从 `OSError` 故障目录和 SIGTERM 中断目录分别恢复第 50 轮保存点，完整训练到第 1050 轮；比较两条恢复路径的全部非计时指标和最终状态。
- 从旧实现的 seed 1234 第 10000 轮目录出发，分别使用旧实现和新实现续训至第 11000 轮；比较旧 `checkpoint.pt` 输入在两侧的行为。

这两种对照分别检查故障恢复和旧格式兼容。原生 H1 的恢复契约仍是 policy + Adam，环境和随机数流重新初始化；不能把这些结果解释为与未中断训练逐步等价。

| 续训路径 | 来源轮数 | 最终轮数 | 新增更新数 | 最终 Adam 步数 |
| --- | ---: | ---: | ---: | ---: |
| `candidate-failure-resumed` | 50 | 1050 | 1000 | 21000 |
| `candidate-interrupt-resumed` | 50 | 1050 | 1000 | 21000 |
| `baseline-legacy-resumed` | 10000 | 11000 | 1000 | 220000 |
| `candidate-legacy-resumed` | 10000 | 11000 | 1000 | 220000 |

SIGTERM 路径实际记录 `ProcessInterrupted: Interrupted by signal 15` 和 `interrupted` 状态，并成功加载第 50 轮。两组续训对照各自的 1000 行非计时指标、最终 policy 和 Adam 状态均精确一致，学习率保持 `0.0003`。四条续训共完成 3,072,000 条新增转换。

最终版本记录已经通过哈希验证的来源权重身份，不会为此重新读取可变的输入文件。从零训练该字段为 `null`，后续加载也不要求历史来源目录存在。额外两条路径从同一故障目录和旧格式目录出发，各新增 1000 轮，与前述候选的相同续训路径对照，以验证这一记录变更。

| 最终版本路径 | 最终轮数 | 来源哈希核验 | 与候选续训的指标 / 状态 |
| --- | ---: | --- | --- |
| `final-failure-resumed` | 1050 | 与实际来源文件一致 | 全部精确相同 |
| `final-legacy-resumed` | 11000 | 与实际来源文件一致 | 全部精确相同 |

额外两条路径各完成 1000 轮，合计 1,536,000 条新增转换；本轮六条完整续训合计 4,608,000 条新增转换。最终版本的 25 项 H1 测试和 ef 回归均在该记录变更后重新通过。

## 固定指令评估

每个完成的从零训练模型评估前进 `(0.5,0,0)`、原地转向 `(0,0,0.5)`、前进转向 `(0.5,0,0.5)`、站立 `(0,0,0)` 四种指令。每次一个环境，最多 1000 个控制步、20 秒，首次终止后停止统计，报告实际观测秒数。

采用确定性标称姿态，关闭训练噪声与随机化。评估 seed 9701 不会创造不同初态；三个训练种子也不等于三次扰动鲁棒性测试。本轮不设置行为验收阈值，因此 `accepted=null`；退出码为零只表示完成评估。提前跌倒路径的 RMSE 只覆盖终止前观测，必须和存活及观测时间一起解读。

下表报告修复后的结果；旧实现的对应指标逐项相同。

| 1234 | 前进 | 否 | 3.18 | 0.4147 | 0.2828 |
| 1234 | 原地转向 | 是 | 20.00 | 0.0831 | 0.5130 |
| 1234 | 前进转向 | 否 | 3.28 | 0.4027 | 0.5657 |
| 1234 | 站立 | 否 | 15.92 | 0.1482 | 0.1172 |
| 4321 | 前进 | 是 | 20.00 | 0.1719 | 0.3803 |
| 4321 | 原地转向 | 否 | 8.12 | 0.1609 | 0.7143 |
| 4321 | 前进转向 | 是 | 20.00 | 0.1529 | 0.5051 |
| 4321 | 站立 | 是 | 20.00 | 0.0512 | 0.2725 |
| 2026 | 前进 | 是 | 20.00 | 0.1701 | 0.2818 |

每侧仅 8/12 个模型与指令组合完整存活。seed 1234 前进试验在 3.18 秒终止；三个模型的原地转向平均角速度分别约为 -0.0055、0.0161、-0.0007 rad/s，明显低于 0.5 rad/s 指令。不能把这批软件对照权重称为合格行走/转向策略。

## 探索性后训练：单独继续一个失败模型

完成上述评估后，选择在四种指令中有三次提前终止的 seed 1234 模型做一次探索性续训。这是观察结果后选出的失败案例，不是新增的独立训练种子，也不并入前面的等预算保存实现对照。

使用最终实现，从第 10000 轮追加 2000 轮，环境数由 32 改为 128，horizon 保持 24，两个 CPU 线程，续训 seed 8801，学习率继承 `0.0003`。完整执行新增 **6,144,000 条环境转换**，最终第 12000 轮、Adam 步数 240000；来源哈希与实际加载文件一致。

完成下文的初始训练后，可从同一保存点复现本节追加阶段：

```bash
python -m embodiedforge h1-native train --headless \
  --resume runs/h1-publication-train --num-envs 128 --horizon 24 \
  --threads 2 --updates 2000 --seed 8801 \
  --output runs/h1-publication-posttrain
```

前后评估保持同一标称起点、seed 9701、一个环境、四种固定指令和最多 20 秒；下表每格按“续训前 → 续训后”列出。

| 指令 | 完整存活 | 实际秒数 | 平面 RMSE，m/s | 转向 RMSE，rad/s |
| --- | --- | --- | --- | --- |
| 前进 | 否 → 是 | 3.18 → 20.00 | 0.4147 → 0.1453 | 0.2828 → 0.1687 |
| 原地转向 | 是 → 是 | 20.00 → 20.00 | 0.0831 → 0.0714 | 0.5130 → 0.5042 |
| 前进转向 | 否 → 是 | 3.28 → 20.00 | 0.4027 → 0.1429 | 0.5657 → 0.2052 |
| 站立 | 否 → 是 | 15.92 → 20.00 | 0.1482 → 0.0665 | 0.1172 → 0.0885 |

这个选定模型的完整存活由 1/4 个指令组合增加到 4/4，四项均完成 20 秒。前进平面 RMSE 从 0.4147 降到 0.1453 m/s，平均前进速度达到 0.4703 m/s；前进转向的转向 RMSE 从 0.5657 降到 0.2052 rad/s。原地转向平均角速度仍只有 0.0019 rad/s，目标为 0.5 rad/s，转向 RMSE 仍为 0.5042 rad/s，因此不能将该模型视为合格的全指令行走策略。

这是单条经过结果筛选的训练链。新增数据量、rollout 批量和恢复后的随机数流同时变化，没有同预算的 32 环境续训对照，不能分离它们各自的作用，也不能据此调整默认算法或宣称普遍提升。评估仍为 `accepted=null`，没有完成扰动、地形或真机验收。

本节单独增加一条完整续训和四次评估；它们不计入前文六条对照续训和 24 次评估的数量。包含本节后，完整训练/续训共执行 56,832,000 条环境转换，三个故障触发运行另计。

## 参数量、权重大小与磁盘成本

H1 的 actor 和 critic 各有三层 128 单元 ELU，观测 69 维、动作 19 维。以下张量字节数来自实际保存状态；纯参数大小不包含 Python 对象、文件头、仿真资产或运行时内存。

| 部分 | 参数 / 状态元素数 | FP32 张量字节 |
| --- | ---: | ---: |
| Actor 网络 | 44,435 | 177,740 |
| Critic 网络 | 42,113 | 168,452 |
| 探索 `log_std` | 19 | 76 |
| 全部可训练参数 | 86,567 | 346,268 |
| Adam 状态 | 173,151 | 692,604 |

Adam 包含两组动量以及 17 个参数张量各自的步数。训练 checkpoint 同时保存 actor、critic、探索参数和 Adam；不能把完整 checkpoint 的大小称为部署 actor 的大小。仿真 `model.mjb` 是编译后的物理模型和网格，也不属于神经网络参数。

| 实际文件 | 字节数 | 含义 |
| --- | ---: | --- |
| 旧格式完整 checkpoint | 1,059,603 | policy + Adam + 元数据 |
| 新格式单个完整 checkpoint | 1,060,407 | 相同模型与优化器状态，文件名进入 ZIP 目录 |
| 新格式保留的两份 checkpoint | 2,120,814 | 当前与前一个提交点 |
| `model.mjb` | 51,615,297 | 物理模型与网格 |

单个新权重文件比旧格式多 804 字节，参数量和张量字节数没有增加。保留前一份保存点额外占用约 1 MiB/运行；这不包含日志、源码快照或 SDK。

本轮从零 PPO 训练不是模仿学习预训练，故障后追加 PPO 也没有引入新的后训练算法。这里的旧/新实现对照只隔离保存发布顺序，不能替代奖励、网络、随机化或预训练方式的算法消融。Microduck 的预训练、后训练和消融设计仍见 [模型与实验说明](microduck-model-training-ablation.md)。

## 复现本次软件对照预算

以下是本次 32 环境软件对照的复现预算，不能作为合格行走配方。日常训练起点见 [H1 指南](h1-native.md) 中的 128 环境、5000 轮示例，并对训练或续训后的策略重新验收。在已安装 H1 依赖的 Python 环境内执行；下列目录必须不存在：

```bash
python -m embodiedforge h1-native train --headless \
  --model /home/ubuntu/workspace/3rdparty/mink/examples/unitree_h1/h1.xml \
  --num-envs 32 --horizon 24 --threads 2 --updates 10000 \
  --seed 1234 --learning-rate 0.0003 --output runs/h1-publication-train
python -m embodiedforge h1-native train --headless \
  --resume runs/h1-publication-train \
  --num-envs 32 --horizon 24 --threads 2 --updates 1000 \
  --seed 8801 --output runs/h1-publication-resumed
python -m embodiedforge h1-native evaluate --headless \
  --run runs/h1-publication-train --num-envs 1 --threads 2 \
  --steps 1000 --seed 9701 --velocity 0.5 0 0 \
  --output runs/h1-publication-forward
```

这些是正常训练、续训和评估命令，不包含故障注入入口。故障脚本仅用于本次独立实验，没有增加产品启动模式。
