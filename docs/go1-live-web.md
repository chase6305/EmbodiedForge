# Go1 在线策略与统一 Web 控制

按步骤执行安装、训练、续训、评估和运行，见 [训练与部署命令](training-deployment.md)（[English](training-deployment.en.md)）。

`embodiedforge live` 加载已有 Go1 PPO checkpoint，以确定性策略实时计算动作并推进
mjbatch / MuJoCo 仿真。浏览器展示实际状态，提供速度指令、暂停、单步、选中环境重置、
相机跟随及渲染器切换。这条入口执行推理，策略参数和归一化统计保持固定。

## 启动

```bash
conda activate ef-viewer
python -m embodiedforge live \
  --run runs/go1-preserve-balanced-s0-1800-20260914

# 同一物理和策略，使用 OVRTX；两个环境可分别设置速度指令
python -m embodiedforge live \
  --run runs/go1-preserve-balanced-s0-1800-20260914 \
  --render-backend rtx --num-envs 2
```

两个示例分别运行，打开 `http://127.0.0.1:8080`。默认暂停、速度指令为零；先选
“前进”等指令，再点“继续”。也支持 `python -m embodiedforge.go1_live`。

查看器环境需要 `viz-robot`，GL/RTX 另需各自依赖。策略运行在训练记录内
`result.runtime.executable` 指定的独立 Python 环境中，无需向查看器环境安装 Torch
或 mjbatch。可显式指定 `--worker-python /path/to/venv/bin/python`，保留虚拟环境
入口路径，不解析成其底层解释器。已有本机运行使用 `.cache/external/mjbatch/.venv`。

输入必须是已完成的 `go1-joystick` 托管训练目录。启动时检查配方及源码 revision、
checkpoint SHA256、迭代号、任务语义、指令/奖励配置、张量有限性和归一化统计。
同时核对训练记录中保存的 MuJoCo、mjbatch、Menagerie、Torch、NumPy 版本。
校验通过只说明输入兼容，不表示该策略在所有指令下都能稳定行走。

## 控制行为

| 控件 | 语义 |
| --- | --- |
| 前进 / 后退 | 选中环境的前向指令 ±0.5 m/s |
| 左移 / 右移 | 选中环境的侧向指令 ±0.3 m/s |
| 左转 / 右转 | 前向 0.3 m/s，加 ±0.5 rad/s 转向 |
| 自定义三个数值 | 前向、侧向和转向指令，在服务端按训练配置范围校验 |
| 指令归零 | 选中环境进入零指令策略；仿真仍继续推进，机器人可能尚有惯性 |
| 暂停 / 继续 / 单步 | 控制全部环境；单步恰好执行一次策略和 0.02 s 控制步 |
| 重置选中 | 只重置指定环境，递增其 episode，并清零其指令与 reward |
| 相机跟随 / 渲染器切换 | 改变显示，不重新加载策略或重置物理 |

页面显示实际 reward、当前指令以及躯干局部坐标系的平面速度和转向角速度。
环境下拉框切换到另一行不会把原来的指令套到新环境上；后端独立保存每行指令。
已应用指令持续有效，直到下一次指令或重置。

Web 输入支持任意范围内的小数。空值、非数值和越界输入会在表单内拦截，Enter 可提交。
页面区分“输入尚未应用”“等待指令生效”和当前指令；预设按钮高亮对应实际生效的指令。
未提交的输入按环境保存，切换回来可以继续编辑；“恢复当前指令”丢弃当前环境的草稿。
请求等待期间继续编辑不会丢失新输入。环境切换完成前，针对环境的操作暂时禁用，
并显示目标环境；页面依据服务端回执更新操作反馈，避免旧状态覆盖新的选择。

点击画面后可使用 W/S 前进后退、A/D 左右移动、Q/E 转向、X 指令归零；每次按键设置
一条持续指令，不是按住行走、松开停止，也不会自动开始仿真。Space 暂停/继续，
N 单步，R 重置选中环境，F 恢复默认视角。输入框内、组合输入及 Ctrl/Alt/Meta 组合键
不会触发这些快捷键；长按重复事件忽略。全屏按钮放大画面及控制面板，Esc 可退出。

连接中断时禁用仿真操作，最后一帧变暗并标明连接状态，页面自动重连；不会自动重发
未确认的操作。断线不暂停服务端仿真，恢复连接后以服务端的实际状态为准。

任一环境摔倒或到达回合上限时，整个会话暂停并保留末态；页面列出需重置的环境，
全部终止行重置后可继续。这里沿用 Go1 任务现有的摔倒判定（up_z < 0），
默认 `--episode-steps 3000`，即 60 s 仿真时间。没有自动重置掩盖终止状态。

`--num-envs` 默认 1，上限 64；`--threads` 默认 2；`--seed` 默认 0。
画面默认 960×540、`--fps 30`。运行速度调整控制步的目标墙钟频率，不改变物理 dt；
实际速率受策略和渲染耗时约束。`--duration` 从首帧成功后开始计时，0 表示持续运行。
停止按钮或 Ctrl+C 关闭页面服务、渲染进程、策略进程及会话临时目录。

分辨率和目标 FPS 也可以在 Web 的“相机与画面”面板中调整，最高目标值为 60 FPS。
画面与物理使用独立墙钟调度，改帧率不重置回合或改变控制 dt。高 FPS 仍可能减少物理
在单位墙钟时间内可执行的步数；60 FPS 不等于 60 个新的策略动作。详见
[画面设置与帧率语义](viewers.md)。

暂停后，画面没有变化时显示“静止”，并停止重复渲染、JPEG 编码和重复帧传输；
指令与状态仍更新。拖动相机、切换环境或重置会重新生成画面，继续运行无需重建渲染器。

## 模型与进程边界

策略进程复用本仓库移植的 Go1 观测、镜像 ActorCritic 和 mjbatch 任务。
每步固定外部指令，关闭随机指令重采样，前向刷新传感器的方式与现有固定指令评价器一致。

策略进程把自身编译的模型导出为临时 MJB，包含网格和材质；查看器读取这份模型，
无需另找“相似的 Go1 XML”。双方核对模型哈希和 MuJoCo 版本，显示 qpos 来自实际仿真。
运行期间固定输入 checkpoint 副本，原训练产物不会被在线操作修改。

Web 主进程通过私有继承 socket 与训练 Python 通信，消息为有长度上限的 JSON；
日志走 stderr，不混入数据通道。HTTP 线程只排队控制请求。渲染继续使用独立进程，
可以在 MuJoCo、OpenGL 和 OVRTX 之间切换；材质支持边界与机器人回放相同。

当前只接通 Go1 在线策略，H1 仍使用记录回放；这里没有训练更新、实机连接或 Web 模型上传。

## 本机验证

2026-09-14 使用 `go1-preserve-balanced-s0-1800-20260914/model.pt`（迭代 1799），
在两个真实 mjbatch 环境中验证在线前进与转向。19 项浏览器检查通过，包含暂停、
单步、指令隔离、局部重置、越界输入拒绝、三种渲染器往返切换、终止末态保留、
终止后重置及正常停止；浏览器未报告 JavaScript 异常。

查看器环境回归：473 passed / 55 skipped。独立训练 SDK 环境：29 passed / 2 skipped，
另有 25 个 subtests；包含真实任务步进、终止冻结、模型导出一致性以及策略权重和
归一化统计保持不变。

另从工作目录外加载安装后的 wheel，完成真实 checkpoint 的跨环境推理、终止冻结与
退出检查：查看器未导入 Torch，策略进程退出码为 0，会话临时目录已删除。
审计文件位于 `runs/go1-live-web-audit-20260914/`。

MuJoCo、OpenGL、OVRTX 均验证了暂停复用画面、状态继续更新、相机操作触发重绘和
切换后保持姿态；还验证了暂停首帧显示、单步、在线控制及终止后重置。
后续记录位于 `runs/web-idle-audit-20260914/`，保留原始审计记录。

交互改进的后续检查位于 `runs/web-interaction-audit-20260914/`：482 项 Python 回归通过

Enter 提交和停止后的迟到响应。另验证 wheel 内包含与源码一致的 HTML 和 JavaScript。
